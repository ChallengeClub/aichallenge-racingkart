# NPC通過状況に応じた適応型速度制御

## 1. 目的

NPCトラッカーのTTC速度スケールを全遭遇で緩めると、182〜183秒台まで短縮できる一方、500秒安定性を再現できなかった。そこで、正面接近では検証済みの線形減速を維持し、NPCが横へ離れている通過状態だけ減速を緩和する状況適応型制御を試作した。

## 2. 状況認識

追跡履歴の先頭と末尾から、NPC中心の横オフセットと横分離速度を計算する。次をすべて満たす時だけ「安全に通過中」と判定した。

- NPCまで2.5 m以上
- 横オフセット0.8 m以上
- 横方向へ0.2 m/s以上の速度でさらに離れている

正面、横方向へ戻ってくるNPC、2.5 m未満の至近距離では、常に従来の線形指数`1.0`を使う。

状況適応時だけ`passing_speed_scale_exponent`を使う。単体テストでは、横へ離れるケースだけ緩和され、正面・接近・至近距離では線形応答になることを確認した。

## 3. 評価結果

| 通過時指数 | NPCあり結果 | 周回値 | 判定 |
|---:|---|---|---|
| 0.75 1回目 | 500秒無停止 | 187.17秒 / 196.99秒 | 安定、効果は約0.5秒 |
| 0.50 | 328.2秒で停止 | 186.76秒 | 不採用 |
| 0.75 2回目 | 301.2秒で停止 | 184.46秒 | 再現せず、不採用 |

指数0.75の1回目は、線形トラッカーv2の2周目約197.5秒に対して約0.5秒短縮し、最大速度2.81 m/sに収まった。しかし2回目は184.46秒まで短縮した後に停止した。指数0.50も同様に500秒未満で停止した。

評価JSONは次に保存した。

- `output/npc-tracker-adaptive-passing-e2e.json`
- `output/npc-tracker-adaptive-passing-050-e2e.json`
- `output/npc-tracker-adaptive-passing-e2e-run2.json`

## 4. 結論

NPCの横位置と横分離速度を使えば、全遭遇の減速を緩める方式より介入を限定できる。正面状態で従来減速へ戻す設計もオンラインで動作した。一方、ランダムNPC条件で2回連続500秒を再現できず、採用には至らなかった。

横分離速度は数フレームの履歴先頭・末尾から求めているため、一時的な角度変化やクラスタ中心の移動で安全判定が早く成立する可能性がある。次に必要なのは、次の状態機械である。

1. 横オフセット条件を複数回連続で満たしてから通過状態へ入る
2. TTCが悪化した場合は即座に線形減速へ戻す
3. 通過状態へ入った後も短時間だけに限定する
4. 適応判定回数と継続時間を評価ログへ記録する

この段階では`adaptive_speed_scale_enabled: false`へ戻し、適応ロジックを次の状態機械評価に残した。その後、連続確認とヒステリシスを追加した版が500秒を2回連続で通過したため、現在の採用判断は[12_Confirmed_Adaptive_Passing_State.md](12_Confirmed_Adaptive_Passing_State.md)を参照する。
